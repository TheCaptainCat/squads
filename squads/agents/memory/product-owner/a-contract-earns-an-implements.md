When linking delivered work to a contract slice, the contract earns the ref only if its own prose or Scope paragraph *states the promise the feature delivers* — adjacency of subject matter is not enough.

Two failure modes this rules out. Filing a feature under the nearest contract because the topic is related hides the gap the link was meant to reveal. Driving a currency warning count to zero is not the goal; an unassigned feature is cheap, a wrong assignment is a lie in the corpus that nobody re-reads.

Practical form: read the six Scope paragraphs first, then judge each feature against them. Add a second ref only when two acceptance criteria land in two different contracts. When a feature has no home, classify it — internal/dev-process work that should never have warned, or a real capability with a missing slice, named. That list is the actual product of the pass.
