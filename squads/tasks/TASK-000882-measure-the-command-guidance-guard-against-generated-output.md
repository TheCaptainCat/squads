## What is wrong

The command-guidance guard measures a corpus that includes this repository's `CLAUDE.md`
**in full** — the hand-written contributor half above the managed markers, not only the
section squads generates. That half is prose this repository wrote for its own
contributors. No adopting squad has it.

So a green run certifies this repository's agent surfaces, not squads' generated surfaces.
That is the wrong subject: the standing rule is to reason from the adopter, not from this
repository, and a gate that quietly measures the dogfood instead of the product is a false
assurance rather than a weak one.

Measured against squads' generated output alone — the twelve generated skill bodies plus
the `CLAUDE.md` managed section — five further commands are named nowhere:

```
graph   import   init   migrate   override
```

Re-measured independently rather than taken from the handoff, with the matcher validated
on known positives first (`create` 50, `tree` 10, a control term 0). The five come back at
zero in both the skill bodies and the managed section. The generated corpus is 8,041
characters of managed section on top of the twelve bodies.

## A sixth, masked

One command is credited by the matcher and named by nothing. **`adopt`** scores two hits in
the managed section; both are the ordinary English verb — "adopt that agent", "not a
persona to adopt" — in the impersonation paragraph. The string `sq adopt` appears in no
generated surface at all. `sq sync` scores one, and that one is real but incidental: the
"regenerated by `sq sync`" warning line every managed region carries.

This is the guard's own stated limit — matching is by name, so a command whose name is an
ordinary word is credited by any prose use of it — arriving as a live case rather than a
hypothetical, on the very category under discussion. It is not fixed here; see the deferral
below.

## The ruling, per command

**`graph` — name it.** It is a read surface, and it is the only absent member of a set that
is otherwise complete: `list`, `tree`, `show`, `search`, `blocked`, `inbox`, `mine`,
`workload` and `reflog` are all present. A complete-looking list is worse than a short one,
because an agent that has learned the read verbs reasonably concludes there is no
ref-graph view. There is one, and its own help calls the `--json` shape "the read surface
for agents and orchestrators" — built for this reader, hidden from them.

**`import` — name it.** The absence has a measurable cost rather than a stylistic one. An
agent handed a bulk or historical entry job without it loops the create verb: N
transactions instead of one, no all-or-nothing validation across the batch, and no correct
way to set historical timestamps. It is also the only verb that makes the global
timestamp-forging option usable as designed. One clause naming the condition — bulk or
historical entry from a prepared file — and the verb.

**`migrate` — name it, for ownership rather than discovery.** This is the one command on
the list an agent meets as a wall: the root callback refuses every other command on a
schema mismatch. But the wall already names its own remedy in the error text, so discovery
is not what is missing. What no surface says is **whose call it is**. Raising a squad's
schema rewrites every item file and is a one-way move for everyone sharing that squad; an
agent that meets the wall mid-task and helpfully runs it has made a release-level decision
alone. Silence here does not leave the agent uninformed, it leaves the agent to be helpfully
wrong. Name the wall, name the verb, and say it is raised with the operator rather than
performed mid-task.

**`override` — name it, with the same ownership clause.** Adopter customisation is
first-class scope, not a hypothetical: only the roster types are reserved and the work-item
vocabulary is meant to be projectable. The failure the absence causes is concrete and bad.
An agent asked to add a status, rename a type or reword a generated surface has no
sanctioned route, so it edits bundled package data under the installed distribution, or
hand-edits a managed file that the regeneration command then discards. Naming the surface
converts an invisible destructive path into a visible one. Naming a door is not sanctioning
walking through it, and the clause should say so: the door exists, and opening it is a team
decision.

The cheatsheet already gestures at this without naming it — it tells the reader a project
may declare its own ref kind and see it rendered. Where it says a project may declare, say
how.

**`init` — exempt.** Generated guidance ships *inside* a squad and is only ever read by an
agent for whom one already exists. A bootstrap verb cannot reach the reader who needs it;
text naming it would be, by construction, never actionable where it is read. The surfaces
that can reach that reader — the root help, which any agent runs first on an unfamiliar
CLI, and the offline docs — already name it. Its exemption reason should name the class,
bootstrap, not just the one verb.

`adopt` belongs to that same class and gets no entry, only because the matcher already
credits it falsely. That asymmetry is an artefact of the matcher and must not be read as an
inconsistent ruling — write it into the reason line so the next reader does not have to
rediscover it.

## The carrier

The reasoning applied on the previous fix of this shape — placement is a judgement, not a
broadcast — is right and is followed here. Applied per command it does not come out the
same way for all four.

`graph`, `import` and `override` go in the **workflow cheatsheet partial**, which reaches
the main skill body, the AGENTS.md managed section and the workflow command through one
edit. `graph` next to the other read verbs; `import` and `override` next to the maintenance
and spec material they belong with. The managed CLAUDE.md region is deliberately not a
carrier for these three, exactly as reasoned before.

`migrate` is the one exception, and it is an exception on the principle rather than against
it. The cheatsheet is reached through a skill the agent is instructed to load; the managed
region is read unconditionally at session start. Every other item here is a how-to whose
reader has already gone looking. This one is a prohibition whose reader has not — the wall
lands before the agent has done anything, possibly before it has loaded a skill, and the
guidance is useless if it sits behind the thing the agent has not yet reached. The managed
region is the surface that carries the constraints imposed on the session, and one line of
ownership belongs there. The cheatsheet may name the verb too, alongside the neighbouring
maintenance verbs; the managed region is the part that is required.

The two pointer templates remain not carriers. That was settled with reasons; it is not
reopened.

## The corpus

Narrow it to squads' generated output. That means splitting `CLAUDE.md`, not dropping it:
the **managed section stays** — it is generated, and every adopting squad receives it — and
the hand-written contributor half comes out. The result is exactly the product's generated
agent surface.

Nothing is lost by the removal. This repository's contributor prose is written for humans
and is not part of what squads ships; measuring against it was the defect, not the
coverage. There is no case for a second assertion over the full file.

The narrowing reddens the gate for five commands the moment it lands, which is the right
pressure only if the guidance lands in the same change. It does. Sequence it the way the
previous guard was sequenced, because a guard whose failure has never been observed proves
nothing:

1. Narrow the corpus first. Watch it fail naming exactly the five, and report the list.
2. Land the guidance and the bootstrap exemption. Watch it pass.
3. Pull the bootstrap entry back out. Watch it fail naming that verb alone, then restore
   it. An exemption never shown to be load-bearing is decoration.

Both directions must keep asserting, and the existing exemption's own falsification must
still hold.

## Register and regeneration

Generated agent text must not name a bundled type, status or role literal — a guard
enforces it and will fail the build. Keep the new wording vocabulary-neutral.

Goldens move with these templates and are **yours**: regenerate them, never hand-edit, then
read the diff. A golden refresh touching lines nobody intended to change means the edit
went wider than planned. The managed-section golden moves here as well as the cheatsheet
ones, because this change touches both templates.

The template manifest regeneration is **not** yours and must not be run. It is already
outstanding from the previous change in this area, and doing this work before that
regeneration means one regeneration covers both rather than two arriving in sequence — that
is a release-ordering call and it belongs to the coordinator. Say in the handoff that the
manifest is still outstanding.

## Explicitly deferred, with the reason

**The matcher.** Crediting a command because its name is an ordinary English word is a
second defect of the same family, and `adopt` is the proof it is live. A stricter matcher
was probed against the generated corpus and it withdraws credit from four more commands —
the bare-verb entry points whose names double as prose — each of which is its own
substantive question about whether that entry point is guided at all. That is a change to
what the guard asserts, not a correction of what it reads, and folding it in here turns a
bounded fix into an open-ended judgement exercise. The probe's own regex was also not
validated against the real invocation forms, so ruling off it now would be legislating from
an unproven measurement.

**The corpus's shape.** The corpus is a hand-listed set of surfaces. A newly generated
agent-facing surface would silently not be measured — the same class of gap as this one,
one level up. Deriving the corpus from what a fresh bootstrap actually generates would
close it. That is a guard-architecture change and does not belong in a release being
brought to a close.

Neither deferral blocks this work, and this work does not depend on either.

## Acceptance

- The guard's corpus is squads' generated output: the generated skill bodies plus the
  `CLAUDE.md` managed section. The hand-written contributor half is not measured.
- `graph`, `import`, `override` and `migrate` are each named in a rendered generated
  surface — verified by rendering, not by reading template source.
- `migrate`'s guidance reaches the `CLAUDE.md` managed region and carries the ownership
  clause, not only the verb.
- `override`'s and `migrate`'s wording names the surface without sanctioning unilateral use.
- The exemption list holds the bootstrap entry with a reason that names the class and
  records why its sibling has no entry.
- The failure was observed at each of the three steps and each observation is reported with
  the exact list the guard named.
- Goldens regenerated rather than hand-edited, diff confined to intended lines.
- The vocabulary guard still passes.
- `uv run --all-extras` for each of `pytest`, `ruff check .`, `ruff format --check .`,
  `pyright`; and `sq check` clean.
- The manifest regeneration is not performed and is flagged in the handoff.
