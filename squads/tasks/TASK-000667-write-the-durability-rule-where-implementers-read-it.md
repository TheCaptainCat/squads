ADR-663's rule is only worth what its weakest call site is, and the ADR names where it has to
be written down: the `_index/_store.py` and `_itemfile.py` module docstrings, because that is
what an implementer reads before adding a mutation. This lands after the write path, the read
path, and the transaction handle are in their final shape, so the prose describes what is
actually there.

## Scope

**`_index/_store.py` module docstring.** Add the skew-direction rule: markdown is always ahead
or equal, the index `os.replace` is the transaction's last write to squad data, and nothing
that mutates an item `.md` may run after the commit. Name the two exemptions (regenerable
artifacts; the reflog's deliberate post-commit append) and the stated failure model — process
death in, host crash and power loss out, with `sq repair` as the recovery path there. Include
the four interrupted-op outcomes (create / update / remove / retype-rename) and why each is
losslessly repairable, and why the inverse skew is forbidden rather than discouraged: an index
ahead of the markdown makes `sq repair` silently revert a committed mutation or resurrect a
removed item, and a loud, repairable inconsistency is strictly better than a quiet rollback.

**`transaction()` docstring correction.** It currently claims "If the body raises, nothing is
written". That is true only of the index — markdown writes already made do stand, and under
this model that is by design. Fix the sentence; do not fix the behaviour.

**`_itemfile.py` module docstring.** The atomic-write primitive's contract: every squad-data
markdown write is a temp-write + fsync + `os.replace` in one thread hop, so a killed process
cannot truncate the source of truth and no reader can observe a partial file. Add that a
transaction writing N markdown files is still not atomic across those N, and that this is fine
because each is durable before the index commits, so the skew stays one-sided for N exactly as
for one.

**Invariants list.** Add the skew-direction rule to the "Invariants — keep these true" section
of the repo's `CLAUDE.md` as a one-liner pointing at the store docstring for the full
statement. Edit only that hand-authored section — the `squads:start`/`squads:end` managed region
is regenerated by `sq sync` and hand-edits there are lost.

## Constraints

- Prose, plus the one optional code change in the second subtask. No other behaviour change.
- No status/lifecycle prose and no ticket ids in source or docstrings.
- The adopter-facing changelog lines for the two observable behaviour changes belong to the
  tasks that produce them — do not duplicate them here.
- `docs/` is adopter-facing and describes the tool, not the engine's internals: this rule
  belongs in the module docstrings and the contributor-facing invariants list, not in a
  published doc page.
- Gate: `uv run --all-extras pyright`, `uv run --all-extras ruff check .`,
  `uv run --all-extras ruff format --check .`, and the suite.

## Acceptance

- A developer adding a new mutation core can read the ordering rule, its exemptions, and the
  failure model without leaving the module.
- `transaction()` no longer claims the markdown side rolls back.
- Either one atomic-write primitive serves both sides, or the reason there are two is recorded
  at the second one.
- `uv run sq check` clean; the suite green.

### ST2 — Fold the index writer onto the shared primitive, or record why not

<!-- sq:subtask:ST2:head -->
**Status:** 🟢 Done
<!-- sq:subtask:ST2:head:end -->

<!-- sq:subtask:ST2:body -->
With the markdown-side primitive in place, `IndexStore._atomic_write` is a second copy of the same
temp-write + fsync + `os.replace` shape. Fold it onto the shared primitive so there is one
implementation of the durability barrier rather than two that can drift.

Do it only if the guarantees survive intact:
- the whole open/write/fsync/replace sequence stays inside a single thread hop, with no `await`
  between the fsync and the rename;
- the index's own JSON serialization stays where it is — the primitive takes text, it does not
  learn about `SquadsDB`;
- the sync bootstrap writer (`_atomic_write_sync`, used by `create_empty`) keeps working on the
  no-event-loop path.

If any of those cannot hold, leave both implementations and record why in a one-line comment at
the index writer. Two deliberate copies with a stated reason beat one that quietly weakened the
barrier.

Acceptance:
- Either the index writer delegates to the shared primitive, or the reason it does not is
  recorded at the call site.
- No `await` sits between the fsync and the rename on either path.
- Existing index-write and bootstrap tests pass unchanged; gate clean.
