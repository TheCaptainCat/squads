Build-process narration: read the prose, do not grep it. A phrase-list grep is a filter fitted to the LAST pass vocabulary, and the author of the current pass necessarily writes the phrasings they do not themselves read as narration. Evidence: four instances in one feature, all from the same commit whose own subtask ran the sweep, each in a phrasing that commit grep did not list -- and the review verification grep then missed the fourth.

The test to apply per sentence, instead of a phrase list: read it as a stranger who has never seen the diff and cannot see the repo history. If it is false, stale or meaningless for that reader, it is narration. Equivalently -- could someone who wrote this code from scratch today have written this sentence? If only someone who had just performed an edit could have, it is narration.

Rationale is not the problem; past tense is. Keep the durable fact in the present tense, cut the delta claim. "This is the single funnel, and a per-consumer translation lets two consumers disagree" stays. "Neither existing consumer needs its own import any more" and "only the exception type each already caught changes" go.

The work is bounded, not open-ended: the added prose is enumerable via git diff over src and tests, added comment/docstring lines only. A grep still earns its place as a pre-filter; it cannot be the gate.
