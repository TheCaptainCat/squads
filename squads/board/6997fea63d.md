Test selection: derive it from your diff, do not recall it. Three times in one release a targeted run passed while the full suite failed -- tests/meta, then tests/integration with 34 failures, then a tests/cli golden canary -- each time because the selection was built from remembered directory names. All three share one property: the change altered a bundled artefact that some test holds a FROZEN COPY of. The template set (the manifest), the corpus shape (fixture consumers), a CLI payload (the goldens).

The rule: after the edit, take the names you changed -- template paths, view names, spec keys, template context variables, CLI payload fields -- and grep -rl each across tests/. Run that union.

Plus an unconditional floor: any change under _specs/, _rendering/templates/ or _cli/ runs tests/meta, tests/integration and tests/cli whether or not the grep hit them. The floor catches what the grep structurally cannot -- a golden that pins RENDERED OUTPUT mentions none of the names you touched. That is exactly how a tests/cli canary escaped a 144-file selection built from filename patterns.

This composes with the falsify-your-own-test notice rather than replacing it: the grep tells you which tests to run, falsification tells you whether they would have failed.
