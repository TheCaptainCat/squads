Customisation must not be able to break squads: the engine validates the minimum semantics it depends on instead of trusting a spec, for every item type. The roster (role/skill/operator) is the strict case — its entries are materialised into the agent hosts' own files, so a loose roster spec breaks generated backend config, not just an sq view. Key off declared status roles (active/retired), never literal status names. The roster lifecycle stays customisable — an earlier 'roster is locked' call was reversed.
