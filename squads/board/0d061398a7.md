Post-0.14 candidate, not scoped yet: retire the `-dev` pseudo-role and scaffold developers as ordinary custom roles.

`is_dev_slug` is `slug.endswith("-dev")` — semantics carried by a spelling, across 69 sites in 13 files. This is the defect class the ref-kinds work already outlawed everywhere else: the engine binds to declared semantic roles, never to literals, with a tests/meta scan enforcing it. The `*dev` sentinel is the last bare string that still means something.

Evidence, all from the 0.14 cycle:
- The `set-default` revert bug needed the same fix in `role_base_from_item` and `dev_base_from_item` — two parallel resolver seams that exist only because of this split.
- A non-dev role whose slug ends in `-dev` crashed `show` and `check`.
- The slug grammar cannot decide the dev shape; we named it undecidable in a test title and shipped it.
- `authoring_owner`'s catalog fallback branch exists to cope with the sentinel.

Shape it would take: a developer role is a role with a declared `tech` field, `sq dev add` becomes a scaffolding convenience over `role activate`, and the playbook names a declared capability instead of `*dev`. Needs an ADR and a migration for existing dev items.

Deliberately NOT in 0.14 — stability at the release point. Raised by op-pierre; parked until the release is out.
