The schema version tracks releases, not commits. While the next release is unpublished, its
runner, for example 0.19 to 0.20, is still a draft.

- A new on-disk change before the release: extend that runner, its `manual` text and its tests.
  Do not add a second schema bump.
- This repo's own squad must keep up with it. If the squad was already migrated by an earlier
  draft of the runner, bring it level by re-running the step on a commit, or with a one-off
  script that rewrites only the affected files. Commit first, then run `sq check` and `sq repair`
  to verify.
- Once a release is published, its runner is frozen. A later change is a new runner in the next
  release.
