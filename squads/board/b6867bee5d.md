Code comments and docstrings stay short: say what the code does and why, in a sentence or two. No release versions (0.14, 0.15), ticket IDs or history in them. Those go stale like ticket IDs do and no gate can catch them. The only exception is a migration runner, which is about a version by definition. Detail belongs in the commit, the ADR or the item.
